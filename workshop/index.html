Offcuts

Approaches that were wrong. They are here because the reasoning is usually more useful than the thing that shipped, and because a portfolio with no failures in it is not a portfolio, it is an advertisement.

  • A colour ramp on the engraving. The obvious way to colour a monochrome plate is to map its luminance through a gradient. It does not work: hatching averages into the middle of the range almost everywhere, so nearly every pixel lands on the same mid stop and you get the original picture under a purple filter. What replaced it treats the plate as ink and paper and decides where the light is separately.
  • The circular portrait frame. It looked like a portrait, which was the point, right up until the lightning grew into an arch and the mask ate the corners it was arcing through. The picture is a rectangle and it gets to stay one.
  • A 3.6 MB GIF. One 256-colour palette across a graded storm sky forces the encoder to dither, and dithering a gradient that the smoke is already warping is close to maximum entropy. The same eight seconds is 746 KB as an animated WebP, which GitHub renders in a README perfectly well.
  • Drive — a game strangers play by opening an issue. Built, playable, and killed the same day. There is already a bot on this profile that takes an issue from anyone on the internet, sanitises it, writes it into the README and closes the issue — so pointing that same machinery at a world instead of a wall was almost free. Someone opens an issue titled move: north, a workflow takes one step, and over a week the internet walks a robot across a floor to a hammer. The prototype worked and the rules held up. What it could not answer is that the README needs a picture, and a picture redrawn on every move is a binary committed to git several times a day, forever — the exact thing the daily robot rotation exists to avoid, which makes it hard to argue for here with a straight face. The unsolved rate limit was close behind: the first thing a curious visitor would meet is "you already moved today."
  • A test that could not fail. I checked the animation looped seamlessly by comparing the first frame against the frame one full loop later. The drawing function wraps its own clock, so those are the same call — it was comparing a frame with itself and reporting a perfect score for a visibly broken loop. This one is the most useful thing on the page: a test you have never watched fail is not evidence.
